# Клиентская запись: перенос мобильного дизайна в приложение

Обычная ссылка `/b/{slug}` и совместимый маршрут `/v2/b/{slug}` используют обновлённый клиентский шаблон. Ручная запись мастера сохранена в отдельном шаблоне.

- Молочный фон, белые карточки, шалфейный акцент.
- Пять дат с реальным количеством вариантов начала визита; полный календарь в нижнем диалоге и переход к ближайшей дате.
- Утро / день / вечер; первые шесть слотов, раскрытие остальных. Выбранное время сохраняется при переключении периода.
- Отдельный серверный шаг контактов с итогом, временем окончания и прежними сообщениями валидации.
- Компактное подтверждение с двумя карточками, кнопкой копирования персональной ссылки и экспортом события `.ics`. Для отменённых, завершённых визитов и неявок успех не показывается.
- RU/EN/AZ. Без JavaScript доступны серверные формы с полным календарём и списком времени.

Ключевые файлы: `frontend/templates/online-v2.html`, `frontend/static/booking-v2.css`, `frontend/static/booking-v2.js`, обработчики записи и календаря.

Проверены Go-тесты обработчиков и HTTP, парсинг шаблонов, синтаксис JavaScript. В браузере проверены отрендеренные рабочие шаблоны с синтетическими данными: переключение периодов, открытие календаря и закрытие Escape с возвратом фокуса, компоновка на ширине 375 px и подтверждение. Это не сквозной тест записи в живую базу. Экранная клавиатура устройства не проверена.

Снимок подтверждения для визуального сравнения: `tmp/booking-design-preview/receipt-mobile.jpg`. Более ранние HTML-концепции сохранены в `design/concepts/`.

Адрес, контакты мастера, TTL-приглашения и клиентские действия переноса/отмены не добавлены: в текущей модели публичной записи нет соответствующих данных или маршрутов.

## Последовательная полировка после unslop-аудита

1. Поле персональной ссылки скрыто; раскрывается и выделяется только при отказе буфера обмена. Без JavaScript остаётся пояснение сохранить адрес страницы.
2. Вверху подтверждения — короткая локализованная дата и начало визита; полный интервал остаётся в карточке. Поддержаны RU/EN/AZ.
3. Подписи и вспомогательные тексты — 14 px с межстрочным интервалом 1.5, включая карточки дат.
4. Периоды собраны в нейтральный переключатель с белым выбранным сегментом. Зелёный акцент остаётся у выбранной даты и времени.
5. Повторяющиеся CSS-селекторы объединены. Цвета вынесены в семантические токены; `--orange` оставлен только как совместимый псевдоним для общего stylesheet.

Go-тесты прошли. Отдельно проверены успешное копирование и отказ буфера обмена; на ширине 375 px визуально проверены подтверждение и переключатель периодов. Обновлённый снимок: `tmp/booking-design-preview/receipt-polished.jpg`.

## Последовательный выбор услуги и времени

Клиентская запись разделена серверными GET-переходами: услуга → дата и время → контакты. На первом экране нет календаря и слотов. На втором остаётся только краткая сводка услуги и действие «Изменить». Переходы работают без JavaScript и поддерживают историю браузера. При возврате дата и допустимое выбранное время сохраняются; после смены услуги сервер проверяет старое время заново. Контакты восстанавливаются прежним механизмом краткоживущего черновика.

Период без времени — обычная текстовая подпись с «Нет мест», без кнопки, рамки, фокуса и действия. Доступные периоды имеют белую поверхность и границу, выбранный — акцентную линию.

## Запуск полного приложения и необязательная цена

Номера и подписи шагов центрированы в трёх одинаковых колонках. Полное приложение запущено через Docker Compose на порту 8080 вместе с PostgreSQL.

Цена услуги необязательна. Новая миграция сохраняет отдельный признак отсутствия цены в услуге и снимке записи: отсутствие суммы отличается от явного нуля. Старые цены сохраняют прежний смысл. Клиентские страницы скрывают сумму и валюту у услуги без цены; мастер может оставить поле пустым и позже отредактировать его. Сгенерированный SQL-код обновлён через sqlc.

Проверен полный HTTP-флоу с базой: три шага, услуги с ценой/без цены/с нулевой ценой, успешная запись, отказ повторной записи на занятое время, приватность подтверждения и неизменность снимка цены после правки каталога. Интеграционные SQL-тесты используют изолированные схемы и транзакции, включая обновление старой схемы.

Проверены Go-тесты разделения экранов и прежние проверки записи; в браузере на 375 px проверены отдельный экран услуги, экран времени, неинтерактивное пустое состояние и обновление ссылки «Изменить» после выбора времени. Снимки: `tmp/booking-design-preview/service-step.jpg` и `times-step.jpg`. Предпросмотр использует отрендеренные шаблоны с фикстурами; сквозная запись в БД не выполнялась.
